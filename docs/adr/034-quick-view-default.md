# ADR-034：唤起后默认进入快取视图，全景按需进入

## 1. 标题与日期

- **标题**：默认视图由「全景」改为「快取」，全景保留为 Tab 一键可达的第二视图
- **日期**：2026-11-24
- **决策者**：HuiW86（方向口头裁决 2026-11-24：「需要 2 个视图，一个满足一秒找到，一个满足看见全局；先用一段时间再说」；本 ADR 待签字）
- **影响范围**：推翻 [[03-product-spec]] v0.31 §13.6 a 的裁点「每次唤起都回到全景」；`src/App.tsx` 唤起落点；新增 `src/components/quick/`；**不动数据库**（`user_version` 仍 18，导出 schema 仍 1.6）
- **Issue**：#50

## 2. Status

`Proposed`

## 3. Context

- **触发事件**：2026-11-24 HuiW86 反馈「设计过度了，视觉上找起来效率不是很高」。
- **使用数据**（#49，Notion 计数截至 2026-11-02）：221 次使用中前 3 条占 50%、前 5 条占 62%；76 条里 44 条为 0 次；Modifier / Composition / 中途口令 / 形态话术均为 0 次。实际用法是「一小撮常用 + 偶尔检索」。
- **全景的成本**：找一条要先判断类型、阶段列（8 列 + 未分组）、工作区三件事；每列很窄、卡片只有标题，没有正文线索（待裁决第 8 项「title-only 后卡面无内容线索」同源），眼睛只能整屏二维扫描。
- **两件不同的事**：「给我那一句」一天几十次，要求一秒；「我手上有什么、哪些该收」一周几次，要求全局。放在同一界面里，两头都不好用。
- **与 [[01-spec]] 哲学二「看见全局 > 操作最快」的关系**：本 ADR 不改 spec（人主笔文档）。它把「看见全局」从**默认**降为**一键可达**；哲学二是否需要改写，等试用数据出来由 HuiW86 决定。

## 4. Options Considered

### Option A：保持全景为默认，只改进全景的视觉

- **优点**：零结构改动。
- **缺点**：八列布局的扫描成本是结构性的，视觉精修（V-01 已做过一轮）解决不了「先判断在哪一列」。
- **否决原因**：用户已经在精修后的全景上反馈找起来慢。

### Option B：快取为默认，全景保留、Tab 可达 ✅

- **描述**：新增「快取」工作区并设为唤起落点。单列列表：输入框自动获得焦点，打字即筛选；全景的常用位 1–9 置顶（同一套位置）；每行「名称 + 正文首行」；右侧显示选中项全文；技能与网站进同一列表。`Tab` 往返全景。
- **优点**：常用条目零扫描（数字键或首位）；检索靠打字而不靠记位置；全景原样保留，可随时回退。
- **缺点**：多一个视图要维护；全景的「位置」整理成果在快取里只体现为 1–9 常用位。

### Option C：只留快取，删全景

- **否决原因**：用户明确要保留「看见全局」；且没有数据证明全景无用，先并存再裁。

## 5. Decision

> **一句话拍板**：选 Option B——唤起后进快取，全景 Tab 一键可达，两者并存试用两周。

### 子决策

1. **常用位共用**：快取的 1–9 就是全景 `panorama_placements.pin_slot`，不另设一套。技能自己的常用位（ADR-033）只在技能工作区生效，快取里技能不占数字位。
2. **排序**：空查询时常用位按号置顶，其余按最近使用倒序，从未用过的垫底；有查询时按命中位置（名称开头 > 名称包含 > 正文包含）分档，档内常用位优先、再按使用次数。**位置不随用量变的只有 1–9**——其余按最近使用排是刻意的：快取回答「最近那句」，全景回答「固定在哪」。
3. **使用记录不变**：话术复制沿用各类条目原有的 `source` 取值（与全景相同），技能走 `record_skill_use`，网站走 `open_website`。条目热度与统计口径不受影响。
4. **试用计数用本机存储，不进库**：`localStorage` 按天记「快取 / 全景 / 技能 / 管理」各贴出几次，设置 · 数据页显示近 14 天合计。理由：区分来源需要给 `usage_records.source` 加取值，那是整表重建迁移、装上就不能降版本，只为一次两周的试验不划算。代价：计数不进备份与导出，清掉应用网页数据即丢失。**试用结束后连同设置页那一行一起删掉。**
5. **唤起卫生沿用全景的例外**：管理里有编辑面板开着时唤起不切走（防丢草稿）；唤起清空快取的输入与选中。
6. **`⌘1–9` 不变**：仍是切相位并复制该相位默认对齐话术，与全景一致；快取的常用位用不带修饰键的 `1–9`（输入框为空时）。

## 6. Consequences

### 正向后果

- 最常用的 5 条在固定位置，按一个数字键即可贴出；其余打两个字即可定位。
- 每行带正文首行，名字相近的条目可以一眼区分。
- 全景不再背「快」的要求，之后可以放心往「复盘 / 整理」方向收。

### 负向后果

- 多一个工作区（Header 五个按钮）。若试用后全景用得少，应在下一个 ADR 里收掉的是全景的默认地位以外的东西，而不是再加视图。
- 试用计数只在本机，换机或清数据即失。

### 未来反悔成本

- 低：无迁移、无导出变更。回退只需把唤起落点改回 `panorama` 并删掉 `src/components/quick/`。

## 7. 试用与裁决

- **时长**：两周（至 2026-12-08 左右）。
- **看什么**：设置 · 数据页「试用计数」。
  - 快取占绝大多数 → 另开 ADR：全景定位为「复盘 / 整理」视图，评估收起相位带、中途口令、漂移账、Modifier / Composition 区等 #49 中 0 使用的模块。
  - 全景用得也不少 → 两视图都保留，删除试用计数。
