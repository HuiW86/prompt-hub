## 交付范围

逆向覆盖五个核心场景：唤起与复制、外部草稿到人工入库、资产删除与恢复、本地备份与导入、会话内口令归因。重点追踪入口、持久化和失败边界；视觉细节、所有编辑器分支、性能与签名发布的真机验收不在本轮验证范围。

已有软件测试实际通过：前端 **536 项 / 45 个文件**，Rust workspace **227 项**（包含 MCP stdio 集成与编译失败护栏）。另有两个临时数据库反例实验，分别确认依赖隔离不等于表级权限、立即重复入库防护不等于草稿终身只入库一次。实验通过表示观察成立，不能读成这些更强保证已经满足。

共享产物为三个 CAP 和一个 PAT，均为 **0.1.0 候选契约**，尚无跨项目迁移证据、公共 SDK 或部署包。对上一轮 xianshiqi 资产进行了语义比较，没有为了数量把不同语义强行合并。

## 本轮采用的文档分工

- 原项目的 `01-spec`、`02-constitution` 决定目标和禁区；当前源码决定实现事实；原始测试记录决定当次验证结果。
- 已有 PRD、产品规范、运维规范与 ADR 用引用承接；本轮补齐架构视图、关键行为证据及复用边界。原文档索引滞后的地方记录为偏差，不批量覆盖原文件。
- 项目的文档 **L0—L5** 表示“宪法、契约、工程规格、实施规格、索引、协作契约”；本体系图中的 **L0—L4** 表示观察深度。两者不映射为同一套层级。
- 第一轮误将“跑体系”理解为启动应用；已停止本轮启动的开发进程。本次分析没有编辑真实资产、修改业务源码或升级依赖。

后续项目待办沿用 [HANDOFF](../../../HANDOFF.md)，本目录的新增核查项是分析结果，不替换其状态真相源。成果不要求用户先批准才可阅读；本轮没有替人宣称新的需求或设计已获认可。
