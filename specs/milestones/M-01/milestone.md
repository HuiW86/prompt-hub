# M-01 全景面板成为唤起后的默认视图

## 一句话成果

用户按快捷键唤起后，可以在一屏内看到全部提示词（按意图分列、按使用情况分三层），按一个键把想要的那条贴出去，并且每次取用都被记数。

## 核心目的

**一眼看到全局，一键贴出，每次都记数。** 全景负责「想起来」，一键负责「快」，记数负责「以后能优化」。完整决策记录见 `docs/adr/031-panorama-default-view.md`（由 I-01 落盘）。

## 为什么做

截至 2026-11-12：库里 76 条、累计 221 次使用，前 3 条占 50%，44 条从未用过，近 90 天用到的只有 19 条。现有仪表盘按阶段、层级、协议组织，常用与未用同样显眼，且要切 Tab 和滚动才能看全。

## 范围

做：

- 新工作区「全景」，唤起后的默认视图。
- 六个意图列（对齐与理解、发散与调研、收敛与方案、执行与验收、打磨与表达、沉淀）加底部一排（中途口令、工具）。
- 每列三层：常用位卡片、在用行、未用行。
- 九个常用位，数字键 1–9 复制并收起。
- 打字筛选，位置不动。
- 分组与常用位可由用户调整，并随导出导入保留。

不做：

- 复盘页（归入 M-02）。
- 应用内 Notion 同步。
- 任何新的资产类型；任何对 `usage_records.source` 取值集合的改动。
- 删除或改动现有仪表盘的功能，它保留为「整理」工作区。

## 术语

| 词 | 含义 |
|---|---|
| 条目 | 未软删除、未弃用的 Macro、场景话术、协议话术、Modifier、Composition |
| 常用位 | 用户指定的 1–9 号位置，每个位置最多一条 |
| 在用 | 最近一次使用距今不超过 90 天 |
| 新 | 创建距今不超过 14 天且使用次数为 0 |
| 未用 | 既不是常用位，也不是在用或新 |

## 验收场景

### S1 一屏看全

1. 库里有 73 条条目，窗口 1280×760。
2. 按全局快捷键唤起。
3. 看到的是全景工作区，不是原仪表盘。
4. 73 条的名称全部可见，页面没有纵向滚动条。
5. 每列标题右侧显示「在用数 / 总数」；常用位显示为带数字键的卡片，在用的显示为亮色行，未用的在分隔线下以小一号暗色显示。
6. 已软删除或已弃用的条目不出现。

### S2 一键贴出并记数

1. 常用位 1 上是「把讨论整理成方案」，其使用次数为 N。
2. 唤起后直接按 `1`。
3. 剪贴板内容等于该条正文，窗口收起。
4. 再次唤起，该条次数显示为 N+1；数据库里多一条该条目的使用记录。
5. 用鼠标点击任意一行，结果相同。

### S3 打字筛选，位置不动

1. 唤起后直接输入「调研」。
2. 名称或正文不含「调研」的条目变暗，含的保持亮色；所有条目的位置与输入前一致。
3. 按 `↵` 复制第一个匹配条目并收起。
4. 再次唤起，筛选框为空。
5. 筛选框有内容时按数字键是输入数字，不触发常用位。

## 审查重点

规格没逐条写、但最可能在真实使用中出问题的地方：

1. **唤起性能**：全景在唤起路径上，宪法 C1 要求 P95 不超过 200ms，改动需附 `bench:hotkey-wake` 结果。
2. **数字键冲突**：现有 `⌘1`–`⌘9` 是相位切换，裸数字键是常用位，两者不能互相吞键；筛选框有内容时裸数字键必须是输入。
3. **旧数据**：导入 1.4 版导出文件不能报错，缺失的布局按默认规则补。
4. **超出一屏**：条目多到放不下时，未用层折叠为「还有 N 条」，不能出现滚动条，也不能把在用的挤出屏幕。
5. **整理态**：在全景里复制时，「复制即隐藏」与整理态的 `suppressHide` 语义保持一致。
6. **宪法 B2**：协议话术与 Macro 并列展示，按 D1 结论并列展示；数据层的表结构与 `usage_records` 语义不变。

## 已自行确定的事项

- 布局存进一张新表 `panorama_placements`，不给五张资产表加列：不碰软删除闸门，也不构成新的资产类型。
- 使用记录的 `source` 沿用各类型现有取值，不新增，避免重建 `usage_records`。
- 「在用」「新」「未用」由 `last_used_at`、`created_at`、`usage_count` 现算，不落库。
- 没有指定分组的条目按默认规则归列：协议话术按相位 ID 映射，其余进「未分组」列（该列为空时不显示）。场景是用户自建数据，不按场景名猜分组。
- 导出数据版本 1.4 升到 1.5，携带布局。
